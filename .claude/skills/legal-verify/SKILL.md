# 법률 정확성 검증 (차등 실행)

챔로드는 법률정보 플랫폼이라 **정확성이 최우선**이다. 그러나 모든 변경에 5종 에이전트를 다 돌리면 토큰이 낭비된다 (에이전트마다 콜드 스타트로 맥락을 처음부터 다시 읽음). 그래서 **변경의 성격을 먼저 판정하고 딱 필요한 만큼만** 돌린다.

## 0단계 — 먼저 변경 성격을 판정 (에이전트 실행 전)

방금 한(또는 하려는) 변경이 아래 어디에 해당하는지 스스로 판정하고, 사용자에게 "이 변경은 Tier N으로 판단해 X 검증을 돌리겠다"고 **한 줄로 알린 뒤** 실행한다. 애매하면 한 단계 높은 Tier를 택한다 (정확성 > 토큰).

| Tier | 변경 성격 | 실행할 검증 | 대략 비용 |
|---|---|---|---|
| **T0** | 오탈자·띄어쓰기·디자인·색상·레이아웃·순수 문구 다듬기 (법률 사실 불변) | **없음** (검증 생략) | 0 |
| **T1** | 기존 법률 문구의 경미한 수정 — 사실관계는 그대로, 표현만 손봄 | `legal-verifier` 1회 | 낮음 |
| **T2** | 법률 절차·요건·수치·조문·기한을 **신규 작성하거나 사실을 바꿈** | `legal-verifier` → `adversarial-refuter` (반박 교차검증) | 중간 |
| **T3** | 새 페이지·새 기능·플로우 변경, 또는 **배포(공개) 직전** | 아래 "풀 스윕" 전체 | 높음 |

**추가 트리거 (Tier와 무관하게 조건 충족 시 항상 실행):**
- 여러 페이지에 중복 등장하는 값(가격·채무한도·변제기간·조문·가상사례 수치·표준생계비)을 하나라도 바꿨다 → **`consistency-checker` 반드시 추가**.

## 각 Tier 실행 방법

### T0 — 검증 생략
법률 사실이 안 바뀌었으면 에이전트를 돌리지 않는다. "T0으로 판단, 법률 검증 생략"만 알린다.

### T1 — legal-verifier 단독
`legal-verifier` 에이전트를 Agent 도구로 실행. 수정한 문구의 파일·줄 범위를 알려주고, 해당 부분만 공식 출처(law.go.kr, easylaw.go.kr, scourt.go.kr, ccrs.or.kr)로 확인하게 한다.
- 판정이 **정확**이면 종료.
- **부정확/과장/확인불가**가 나오면 수정 후 Tier를 T2로 올려 반박까지 돌린다.

### T2 — 반박 교차검증 (핵심 워크플로우)
사용자가 명시적으로 선호한 **상호반박 방식**이다. 순서를 지킨다:
1. `legal-verifier` — 변경한 법률 내용을 공식 출처로 검증. 판정·근거·수정안을 받는다.
2. `adversarial-refuter` — legal-verifier의 판정과 수정안을 넘겨주고 **틀렸다고 가정하고 반박**하게 한다.
   - `CONFIRMED`: 반박 실패 → 판정 신뢰, 반영.
   - `REFUTED`: 반박 성립 → legal-verifier 판정을 버리고 재작성 후 다시 이 단계.
   - `UNCERTAIN`: 확정 보류 → 사용자에게 불확실성을 명시하고 공식 출처 직접 확인을 안내.
3. 반박을 통과한 내용만 최종 반영한다.

### T3 — 풀 스윕 (새 기능 / 배포 직전)
법률 정확성 + 여정 + 결핍 + 일관성을 모두 본다. 아래를 병렬로 실행할 수 있다:
- **법률 축**: `legal-verifier` → `adversarial-refuter` (T2와 동일)
- **여정·결핍 축 (반드시 짝으로)**:
  - `journey-auditor` — 페르소나로 흐름을 끝까지 추적해 **있는 것의 오류**를 찾음.
  - `gap-auditor` — **사이트를 읽기 전에** 독립 기준(신청자가 할 일·질문 30개+·막히는 지점)을 먼저 만든 뒤 대조해 **없어서 문제인 것**을 찾음.
  - ⚠️ 이 둘은 반드시 함께 돌린다. journey-auditor 혼자서는 결함(존재하는 오류)만 잡고 **결핍(부재)은 구조적으로 못 잡는다** — 과거 관할법원 안내 부재·온보딩 혼란을 전부 사용자가 직접 발견했던 교훈.
- **일관성 축**: `consistency-checker` — 페이지 간 수치·조문·용어·패키지 키 모순 전수 대조.

풀 스윕 결과는 심각도순(P0 동작오류·잘못된 법률안내 → P1 오해소지·데이터불일치 → P2 UX)으로 취합해 보고한다.

## 실행 시 원칙

- **콜드 스타트 절약**: 각 에이전트에게 변경한 파일·줄 범위를 구체적으로 지정해 불필요한 전수 탐색을 줄인다. 단, gap-auditor에게는 범위를 좁혀주지 않는다 (전체를 봐야 결핍이 보임).
- **거짓 반박이 최악**: adversarial-refuter가 UNCERTAIN이면 REFUTED로 처리하지 않는다.
- **훈련 지식으로 단정 금지**: 모든 법률 판정은 공식 출처 조회 결과에 근거한다.
- **목업 금지 준수**: 결핍 감사에서 나온 기능 제안은 백엔드 없음(localStorage)·법률대리 아님 방침을 존중한다.
- 검증이 끝나면 무엇을 어느 Tier로 돌렸고 결과가 어땠는지 사용자에게 요약한다. 생략한 검증이 있으면 그것도 명시한다 (묵시적 누락 금지).
